## 1. 通用约定

### 1.1 基础信息

| 项 | 约定 |
| --- | --- |
| 接口前缀 | 所有接口以 `/api` 开头，前端 `baseURL` 使用相对路径 `/api`，配合 Vite 代理 |
| 请求格式 | `Content-Type: application/json` |
| 鉴权方式 | 除登录接口外，均需在请求头携带 `Authorization: Bearer <token>` |
| 日期格式 | 日期 `yyyy-MM-dd`（如 `2026-10-11`），时间 `yyyy-MM-dd HH:mm:ss` |
| 金额/数量 | 数字类型，保留 2 位小数，前端以 `number` 处理 |
| 字段命名 | 接口 JSON 字段统一使用 **camelCase**（与 DB 的 snake_case 通过 MyBatis-Plus 自动映射） |
| 接口文档页 | knife4j 自动生成，访问 `/doc.html` |

### 1.2 统一返回结构

所有接口返回统一包装为 `Result<T>`：

```ts
interface Result<T> {
  code: number;    // 业务码，200 表示成功
  message: string; // 提示信息
  data: T;         // 业务数据，失败时为 null
}
```

分页接口的 `data` 统一为 `PageResult<T>`：

```ts
interface PageResult<T> {
  total: number; // 总记录数
  list: T[];     // 当前页数据
}
```

### 1.3 错误码约定

| code | 含义 | 触发场景 |
| --- | --- | --- |
| 200 | 成功 | 正常返回 |
| 400 | 参数错误 | `@Validated` 校验失败、参数缺失/格式错误 |
| 401 | 未认证 | 未登录、Token 缺失或过期 |
| 403 | 无权限 | 无权访问的资源 |
| 500 | 系统异常 | 未捕获异常，由全局异常处理器兜底 |
| 1001 | 库存不足 | 出库/销售数量超过批次剩余数量 |
| 1002 | 批次状态不允许 | 对已过期/已下架批次执行了不允许的操作 |
| 1003 | 出库原因与批次不匹配 | 选择「过期丢弃」但批次未过期 |
| 1004 | 成品已过期禁止销售 | 销售过期批次 |

> **HTTP 状态码与业务码（`code`）约定**：
> - 业务接口的 HTTP 状态码统一为 `200`，业务结果以 `Result.code` 为准（如登录失败 `code=401`、参数校验失败 `code=400`）。
> - 未登录（Token 缺失/过期）与无权限由 Spring Security 过滤器直接返回 `HTTP 401` / `HTTP 403`，响应体同样是 `Result` 结构（`code=401`/`403`）。
> - 前端 Axios 拦截器需**同时**处理两类情况：HTTP 状态码为 `401`/`403` 时直接跳登录/提示；HTTP `200` 时再判断 `Result.code` 是否为 `200`。

## 2. 枚举定义

与 `schema.sql` 中状态字段取值一一对应：

```ts
// 原材料批次状态
type MaterialStatus = 'IN_STOCK' | 'NEAR_EXPIRY' | 'EXPIRED';
// IN_STOCK 在库 / NEAR_EXPIRY 临期 / EXPIRED 已过期

// 原材料出库原因
type OutboundReason = 'NORMAL_CONSUME' | 'EXPIRED_DISCARD';
// NORMAL_CONSUME 正常烘焙消耗 / EXPIRED_DISCARD 过期丢弃

// 成品货架状态
type ShelfStatus = 'ON_SALE' | 'DISCOUNT' | 'OFF_SHELF' | 'EXPIRED_OFF';
// ON_SALE 在售 / DISCOUNT 临期降价 / OFF_SHELF 已下架 / EXPIRED_OFF 过期下架

// 销售类型
type SaleType = 'NORMAL_SALE' | 'DISCOUNT_SALE';
// NORMAL_SALE 正常销售 / DISCOUNT_SALE 临期降价
```

## 3. 认证模块

### 3.1 登录

- **POST** `/api/auth/login`

请求体：

```json
{
  "username": "admin",
  "password": "123456",
  "rememberMe": true
}
```

响应示例：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "token": "eyJhbGciOi...",
    "adminId": 1,
    "username": "admin",
    "realName": "店长"
  }
}
```

**规则**：登录成功后签发 Token，前端保存并随请求携带；密码错误返回 `401`。`rememberMe` 为 `true` 时签发 7 天有效期的 Token（默认不传为 24 小时），用于一段时间内免登录。

### 3.2 登出

- **POST** `/api/auth/logout`

无请求体，携带 `Authorization` 头即可。响应 `code: 200`，前端清除本地 Token。

### 3.3 获取当前用户信息

- **GET** `/api/auth/info`

响应 `data`：

```json
{
  "adminId": 1,
  "username": "admin",
  "realName": "店长"
}
```

### 4.2 原材料批次与库存

#### 4.2.1 批次库存分页查询

- **GET** `/api/material/batch/page`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| pageNum / pageSize | number | 是 | 分页 |
| materialId | number | 否 | 按原材料过滤 |
| status | string | 否 | 按状态过滤，取值见 `MaterialStatus` |
| keyword | string | 否 | 按原材料名称模糊查询 |

响应 `data.list` 元素：

```ts
interface MaterialBatchVO {
  id: number;
  materialId: number;
  materialName: string;       // 冗余返回，便于展示
  unit: string;
  productionDate: string;     // yyyy-MM-dd
  expiryDate: string;         // yyyy-MM-dd
  nearExpiryDays: number;     // 临期阈值
  quantity: number;           // 剩余数量
  status: MaterialStatus;
  remainingDays: number;      // 剩余保质期天数（实时计算：expiryDate - today）
}
```

#### 4.2.2 原材料入库

- **POST** `/api/material/inbound`

请求体：

```json
{
  "materialId": 1,
  "quantity": 10.5,
  "productionDate": "2026-10-01",
  "nearExpiryDays": 5,
  "supplier": "XX供应商"
}
```

**业务规则**：

1. 过期日期由后端根据 `material.shelf_life_days` 自动计算：`expiryDate = productionDate + shelfLifeDays`。
2. 每次入库生成一条 `material_batch` 批次记录（含 `near_expiry_days`）。
3. 入库后写一条 `material_inbound` 流水；`operator` 取当前登录管理员。
4. 入库时若 `productionDate` 已导致过期（`remainingDays < 0`），允许入库但状态初始化为 `EXPIRED`，并提示。

#### 4.2.3 原材料出库

- **POST** `/api/material/outbound`

请求体：

```json
{
  "batchId": 1,
  "quantity": 2,
  "reason": "NORMAL_CONSUME"
}
```

**业务规则**：

1. `quantity` 不得大于该批次剩余数量，否则返回 `1001`。
2. `reason = EXPIRED_DISCARD`：仅允许对 `status = EXPIRED` 的批次操作，否则返回 `1003`。
3. `reason = NORMAL_CONSUME`：禁止对已过期批次出库；对 `NEAR_EXPIRY` 批次允许出库，但前端需提示确认。
4. 出库成功后扣减批次数量，并写 `material_outbound` 流水。

#### 4.2.4 出库流水查询

- **GET** `/api/material/outbound/page`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| pageNum / pageSize | number | 是 | 分页 |
| reason | string | 否 | 按出库原因过滤 |
| startDate / endDate | string | 否 | 按出库时间范围过滤 |

响应 `data.list` 元素：

```ts
interface OutboundVO {
  id: number;
  materialName: string;
  batchId: number;
  quantity: number;
  reason: OutboundReason;
  operator: string;
  createdAt: string;
}
```

```ts
  id: number;
```

```ts
  productName: string;
  price: number;

  nearExpiryDays: number;
  quantity: number;
  status: ShelfStatus;
  remainingDays: number; // 实时计算
}
```

#### 5.2.2 成品上架

- **POST** `/api/product/on-shelf`

请求体：

```json
{
  "productId": 1,
  "quantity": 20,
  "productionDate": "2026-10-11",
  "nearExpiryDays": 2
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| productId | number | 是 | 成品ID |
| quantity | number | 是 | 上架数量 |
| productionDate | string | 是 | 生产日期 yyyy-MM-dd |
| nearExpiryDays | number | 是 | 临期阈值（天） |

**业务规则**：

1. 过期日期后端自动计算：`expiryDate = productionDate + product.shelfLifeDays`。
2. 上架生成 `product_batch` 批次，初始状态：`remainingDays <= nearExpiryDays` 时为 `DISCOUNT`，否则为 `ON_SALE`；已过期则初始为 `EXPIRED_OFF` 并提示。

#### 5.2.3 成品下架

- **POST** `/api/product/off-shelf`

请求体：

```json
{
  "batchId": 1,
  "quantity": 5
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| batchId | number | 是 | 批次ID |
| quantity | number | 是 | 下架数量 |

**业务规则**：

1. 手动下架：`quantity` 大于 0 时，扣减货架可售数量；若扣减后剩余为 0，则该批次状态置为 `OFF_SHELF`。
2. 过期下架：由后端**定时任务**每日扫描，将 `remainingDays < 0` 的在售批次状态自动置为 `EXPIRED_OFF`（也可在查询时动态标记），无需前端手动触发。

#### 5.2.4 成品销售

- **POST** `/api/product/sale`

请求体：

```json
{
  "batchId": 1,
  "quantity": 3,
  "saleType": "DISCOUNT_SALE",
  "actualPrice": 9.90
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| batchId | number | 是 | 批次ID |
| quantity | number | 是 | 销售数量 |
| saleType | string | 是 | 销售类型：NORMAL_SALE/DISCOUNT_SALE |
| actualPrice | number | 否 | 实际成交单价（元），临期降价时必填且需小于原价；正常销售忽略（按原价） |

**业务规则**：

1. `quantity` 不得超过批次剩余数量，否则返回 `1001`。
2. 批次状态为 `OFF_SHELF` 或 `EXPIRED_OFF` 时禁止销售，返回 `1002`；已过期批次销售返回 `1004`。
3. `saleType = NORMAL_SALE`：`actualPrice` 应为原价（等于 `product.price`）。
4. `saleType = DISCOUNT_SALE`：批次须处于临期（`DISCOUNT`）状态，`actualPrice` 为折扣价，需 < 原价。
5. 销售成功后扣减货架库存，写 `sale_record`（`original_price` 后端取 `product.price`，`actual_price` 取请求值）。

#### 5.2.5 销售记录查询

| 参数 | 类型 | 必填 | 说明 |

## 7. 关键业务规则实现说明（供后端开发参考）

1. **保质期计算**：`expiryDate = productionDate + shelfLifeDays`；`remainingDays = expiryDate - today`（整天数）。
2. **临期判定**：`remainingDays <= nearExpiryDays` 视为临期，其中 `nearExpiryDays` 为入库/上架时逐批次填写的阈值。
3. **状态维护机制**：建议后端提供**每日定时任务**扫描 `material_batch` 与 `product_batch`：
   - 原材料：`remainingDays < 0` → `EXPIRED`；`0 <= remainingDays <= nearExpiryDays` → `NEAR_EXPIRY`；否则 `IN_STOCK`。
   - 成品：`remainingDays < 0` → `EXPIRED_OFF`；`0 <= remainingDays <= nearExpiryDays` → `DISCOUNT`；否则 `ON_SALE`（手动下架批次保持 `OFF_SHELF` 不动）。
   - 查询接口同时实时返回 `remainingDays`，前端据此做高亮展示。
4. **数据一致性**：入库、出库、上架、下架、销售均须在**事务**内完成（写流水 + 更新批次数量），失败回滚。
5. **权限与操作人**：所有写操作由后端从 Token 中解析当前管理员，作为流水表 `operator` 字段写入。
