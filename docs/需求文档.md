## 1. 项目概述

### 1.1 项目背景

小云烘焙店日常经营涉及两大类物资管理：

1. **原材料**：面粉、黄油、鸡蛋、奶油、酵母等烘焙原料，采购入库后在生产烘焙时消耗出库。
2. **成品**：面包、蛋糕、饼干等制作完成的产品，上架到货架进行销售。

由于原材料和成品**均有保质期**，人工记账容易出现临期未处理、过期误用等问题，导致物料浪费或食品安全隐患。
本系统旨在实现原材料库存与成品货架的数字化管理，重点解决**保质期监控**、**临期预警/降价**、**过期处置**三大痛点。

### 1.2 项目目标

- 实现管理员登录认证，保障系统访问安全。
- 实现原材料库存的入库、出库全流程管理，并区分出库原因。
- 实现成品的上架、下架、销售管理，并区分销售类型。
- 实现临期、过期物料的自动识别与预警。
- 提供统一数据看板，直观展示库存、货架、销售、临期/过期等核心指标。

### 1.3 使用角色

| 角色 | 说明 | 权限范围 |
| --- | --- | --- |
| 管理员（Admin） | 店主/店员 | 全部功能：登录、原材料出入库、货架上下架、销售登记、看板查看 |

> 首期仅一名或多名管理员共用同一套权限，不区分角色等级。

## 4. 详细功能需求

### 4.1 管理员登录认证

| 编号 | 功能点 | 需求描述 |
| --- | --- | --- |
| AUTH-01 | 登录 | 输入用户名 + 密码登录，成功后签发 Token，前端保存并随请求携带 |
| AUTH-02 | 鉴权 | 除登录接口外，其余接口均需携带有效 Token，否则返回 401 |
| AUTH-03 | 登出 | 清除前端 Token 并跳转登录页 |
| AUTH-04 | 密码安全 | 密码存储使用 BCrypt 等不可逆加密，禁止明文 |

**验收要点**：未登录访问受保护页面自动跳转登录页；登录后 Token 过期自动退出。

### 4.2 原材料库存管理

原材料入库/出库均以**批次（lot）**为单位，每批次独立记录生产日期与保质期，以便精确判断临期与过期。

#### 4.2.1 原材料入库

| 编号 | 功能点 | 需求描述 |
| --- | --- | --- |
| MAT-01 | 新增原材料 | 维护原材料基础信息：名称、分类、单位、保质期天数、存储条件等 |
| MAT-02 | 入库登记 | 选择原材料，录入：入库数量、生产日期、过期日期（或按保质期天数自动计算）、临期阈值（天）、供应商、入库人 |
| MAT-03 | 批次生成 | 每次入库生成一个批次记录，记录生产日期、过期日期与临期阈值 |
| MAT-04 | 库存更新 | 入库成功后对应原材料库存数量累加，并生成入库流水 |

#### 4.2.2 原材料出库

| 编号 | 功能点 | 需求描述 |
| --- | --- | --- |
| MAT-05 | 出库登记 | 选择批次，录入出库数量与出库原因 |
| MAT-06 | 出库原因 | 出库原因必须区分，至少包含：**正常烘焙消耗**、**过期丢弃**（见 4.2.3） |
| MAT-07 | 库存扣减 | 出库成功后对应批次/原材料库存数量扣减，并生成出库流水 |
| MAT-08 | 数量校验 | 出库数量不得大于该批次可用库存，超量时禁止并提示 |

#### 4.2.3 出库原因定义

| 出库原因 | 枚举值 | 说明 |
| --- | --- | --- |
| 正常烘焙消耗 | `NORMAL_CONSUME` | 生产领料，正常消耗出库 |
| 过期丢弃 | `EXPIRED_DISCARD` | 原材料已过期，报废丢弃出库 |

**业务规则**：
- 选择「过期丢弃」时，仅允许选择已过期批次（系统校验，防止误操作）。
- 「正常烘焙消耗」默认只能消耗未过期批次，临期批次出库时给予提示（允许但需确认）。

#### 4.2.4 原材料临期 / 过期处理

| 编号 | 功能点 | 需求描述 |
| --- | --- | --- |
| MAT-09 | 临期预警 | 原材料批次剩余保质期 ≤ 该批次入库时填写的临期阈值时，标记为「临期」，在列表与看板中高亮提示 |
| MAT-10 | 过期识别 | 过期日期早于当前日期时，自动标记为「已过期」，提示管理员尽快执行「过期丢弃」出库 |
| MAT-11 | 状态标记 | 每批原材料维护状态：`在库` / `临期` / `已过期` |

### 4.3 货架管理（成品）

成品同样以批次管理生产日期与保质期。

#### 4.3.1 成品基础信息

| 编号 | 功能点 | 需求描述 |
| --- | --- | --- |
| PROD-01 | 成品维护 | 维护成品名称、分类、售价、保质期天数、生产日期等 |

#### 4.3.2 成品上架

| 编号 | 功能点 | 需求描述 |
| --- | --- | --- |
| PROD-02 | 上架登记 | 成品制作完成后上架，录入：成品、生产日期、过期日期、临期阈值（天）、上架数量、售价 |
| PROD-03 | 上架状态 | 上架成功后将货架库存增加，状态为「在售」 |
| PROD-04 | 临期判断 | 上架或每日扫描时，若剩余保质期 ≤ 上架时填写的临期阈值，自动切换为「临期降价」状态 |

#### 4.3.3 成品销售

| 编号 | 功能点 | 需求描述 |
| --- | --- | --- |
| PROD-05 | 正常销售 | 未临期成品按原价销售，扣减货架库存，生成销售记录 |
| PROD-06 | 临期降价 | 临期成品可按折扣价销售，销售类型标记为「临期降价」 |
| PROD-07 | 过期下架 | 成品过期后自动/手动下架，禁止继续销售，进入待处理状态 |

**销售类型定义**：

| 销售类型 | 枚举值 | 说明 |
| --- | --- | --- |
| 正常销售 | `NORMAL_SALE` | 按原价正常售卖 |
| 临期降价 | `DISCOUNT_SALE` | 临期成品打折售卖 |

**业务规则**：
- 临期成品可以按折扣价销售，销售记录中需记录原价与折扣价，便于统计损耗。
- 过期成品系统强制禁止销售（前端禁售 + 后端校验）。

#### 4.3.4 成品下架

| 编号 | 功能点 | 需求描述 |
| --- | --- | --- |
| PROD-08 | 手动下架 | 管理员可主动将成品下架（如滞销调整） |
| PROD-09 | 过期下架 | 过期成品自动标记为「已过期下架」，不计入可售库存 |
| PROD-10 | 下架状态 | 货架状态维护：`在售` / `临期降价` / `已下架` / `过期下架` |

## 5. 核心业务规则汇总

### 5.1 保质期相关

1. 原材料与成品均维护**生产日期**与**保质期天数**，系统自动计算过期日期：`过期日期 = 生产日期 + 保质期天数`。
2. 剩余保质期天数 = `过期日期 - 当前日期`（取整天数）。
3. 临期阈值**不统一**：入库/上架时针对每个批次单独填写，随批次记录保存；临期判断以该批次填写的阈值为准（例如面粉填 5 天、奶油填 2 天）。
4. 过期判断：`过期日期 < 当前日期`（即剩余天数 < 0）。

### 5.2 原材料出库规则

1. 出库必须指定出库原因，枚举为 `NORMAL_CONSUME` / `EXPIRED_DISCARD`。
2. 「过期丢弃」仅限已过期批次，系统强校验。
3. 临期批次正常出库时给出提示确认，避免浪费。

### 5.3 成品销售规则

1. 未临期成品 → 正常销售（原价）。
2. 临期成品 → 临期降价销售（折扣价，记录原价与折扣价）。
3. 过期成品 → 过期下架，禁止销售。

### 5.4 状态与枚举统一

| 领域 | 枚举 | 取值 |
| --- | --- | --- |
| 原材料批次状态 | `MaterialStatus` | `IN_STOCK`（在库）、`NEAR_EXPIRY`（临期）、`EXPIRED`（已过期） |
| 出库原因 | `OutboundReason` | `NORMAL_CONSUME`、`EXPIRED_DISCARD` |
| 成品货架状态 | `ShelfStatus` | `ON_SALE`（在售）、`DISCOUNT`（临期降价）、`OFF_SHELF`（已下架）、`EXPIRED_OFF`（过期下架） |
| 销售类型 | `SaleType` | `NORMAL_SALE`、`DISCOUNT_SALE` |

> 状态与枚举在代码中一律使用常量/枚举定义，禁止魔法数字。

## 6. 数据模型设计（草案）

### 6.1 表结构清单

| 表名 | 说明 | 关键字段 |
| --- | --- | --- |
| `admin` | 管理员表 | id, username, password, real_name, created_at |
| `material` | 原材料基础信息 | id, name, category, unit, shelf_life_days, storage_condition |
| `material_batch` | 原材料批次（库存） | id, material_id, production_date, expiry_date, near_expiry_days, quantity, status |
| `material_inbound` | 原材料入库流水 | id, material_id, batch_id, quantity, supplier, operator, created_at |
| `material_outbound` | 原材料出库流水 | id, material_id, batch_id, quantity, reason, operator, created_at |
| `product` | 成品基础信息 | id, name, category, price, shelf_life_days |
| `product_batch` | 成品批次（货架库存） | id, product_id, production_date, expiry_date, near_expiry_days, quantity, status |
| `sale_record` | 销售记录 | id, product_id, batch_id, quantity, sale_type, original_price, actual_price, created_at |

### 6.2 关键字段约定

- 所有表均含 `id`（主键）、`created_at`（创建时间）、`updated_at`（更新时间）。
- 状态字段存枚举的 `code` 或英文名，不存裸数字。
- 价格、金额使用 `DECIMAL(10,2)`，数量使用 `DECIMAL(10,2)` 或 `INT` 视单位而定。

## 7. 接口设计约定

- 统一返回结构：`Result<T>`，包含 `code`、`message`、`data`。
- 分页参数统一：`pageNum`、`pageSize`。
- 所有接口路径使用 `/api` 前缀（前端 baseURL 相对路径，配合 Vite 代理）。
- 接口文档通过 knife4j 自动生成，访问地址 `/doc.html`。

**核心接口示例（草案）**：

| 模块 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 认证 | POST | `/api/auth/login` | 登录 |
| 原材料 | POST | `/api/material/inbound` | 入库 |
| 原材料 | POST | `/api/material/outbound` | 出库（含出库原因） |
| 原材料 | GET | `/api/material/list` | 库存列表（含临期/过期状态） |
| 货架 | POST | `/api/product/on-shelf` | 上架 |
| 货架 | POST | `/api/product/off-shelf` | 下架 |
| 货架 | POST | `/api/product/sale` | 销售（含销售类型） |
| 看板 | GET | `/api/dashboard/overview` | 看板统计 |

| 类别 | 需求 |
